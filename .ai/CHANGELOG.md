# Rule Changes Changelog

History of changes to the AI assistant rule system (`.ai/`, `CLAUDE.md`, `AGENTS.md`,
`GEMINI.md`, `.claude/`, `.codex/`). Every rule change gets an entry here — see
`universal/08-rules-evolution.md` for the protocol.

Format: date, what changed, why, who decided. Newest first.

## 2026-10-12 — The audit log in the project modules

**What changed.** `project/10-project-map.md` lists the `Logs` sheet and `src/logs.js`;
`project/12-domain-rules.md` requires every new user-facing operation to call `logEvent_`.

**Why.** The owner asked for every action to be logged; without the rule, the next feature
would silently skip the log. A constraint the owner stated, allowed without approval.

**Decided by.** Owner instruction of 2026-10-12, recorded by the agent.

## 2026-10-12 — Supported chart-area options

**What changed.** `project/12-domain-rules.md` records that `chartArea` accepts only `left`,
`top` and `backgroundColor`.

**Why.** Google rejected `chartArea.bottom` in the owner's real spreadsheet and the rebuild
failed. A constraint learned from a real failure, allowed without approval.

**Decided by.** Agent, while fixing the owner-reported error of 2026-10-12.

## 2026-10-12 — Stats sheet and the execution-time rule

**What changed.** `project/10-project-map.md` lists the Stats sheet and `src/stats.js`.
`project/12-domain-rules.md` forbids per-cell calls and range lists over calendar-sized
ranges (naming the 6-minute limit) and records that only `SUMIF` / `COUNTIF` expand inside
`ARRAYFORMULA`.

**Why.** The owner's year-long calendar hit the execution limit in v2.3.1 — the same
defect class must not return; the Stats sheet changed the sheet set. A new constraint
learned from a real failure and factual additions, allowed by
`universal/08-rules-evolution.md` without approval.

**Decided by.** Agent, as part of the owner-requested Stats work of 2026-10-12.

## 2026-10-12 — Rules in the project modules

**What changed.** `project/10-project-map.md` lists the Rules sheet and `src/trackers.js`;
`project/11-commands.md` points real-sheet verification at `docs/manual-test-plan.md`;
`project/14-config-reference.md` (extended tier) documents `rules` and the tracker layer.

**Why.** The owner-requested rules feature changed the sheet set, the module list and the
config format; the manual test plan is the new place for real-sheet checks. Factual
additions, which `universal/08-rules-evolution.md` allows without approval.

**Decided by.** Agent, as part of the owner-requested rules feature of 2026-10-12.

## 2026-10-12 — The rule system arrives, adapted from CogniBoiler and codepack

**What changed.** Daily Quest gains the assistant rule system the owner runs in `codepack`,
`CogniBoiler` and `learning`:

- `.ai/universal/01–09` copied unchanged from CogniBoiler (portable modules).
- `.ai/project/10–14` written for this project: the map with the language policy and product
  guardrails, the npm commands and the no-pull-request publishing policy, Apps Script domain
  rules, progress tracking over `docs/`, and a config reference marked `tier: extended`.
- `CLAUDE.md` imports every module; `AGENTS.md` is generated by `scripts/sync-agents.mjs`
  (`npm run sync-agents`) with the same 30 KiB budget and tier rules; `GEMINI.md` points
  Gemini CLI at `AGENTS.md`.
- `.claude/agents` and `.claude/skills` are the source; `.codex/agents` and `.codex/skills`
  are generated from them instead of being maintained by hand as in CogniBoiler, and
  `npm run check` fails when the mirror drifts.

**Why.** The owner asked for every AI agent to get up to speed quickly and work as one brain,
by analogy with the owner's other repositories.

**Adapted, not copied.** The sync tool is Node (the project's stack) instead of Python or
Rust; state documents live in `docs/` and are English, because the owner ruled that
everything in this repository is English (2026-10-12, recorded in `docs/decisions.md`).

**Decided by.** Owner, 2026-10-12.
